# Inequality (mathematics)

An inequality is a relation that makes a non-equal comparison between two numbers or expressions. The basic signs are `<` (less than) and `>` (greater than), read left-to-right: `a < b` means `a` is strictly smaller than `b`.

Two refinements matter. **Strict** inequalities (`<`, `>`) exclude equality. **Non-strict** inequalities (`≤`, `≥`) allow equality: `a ≤ b` means `a` is smaller than or equal to `b`, i.e. "at most `b`". The slashed forms `≮` and `≯` say "not less than" and "not greater than". `≪` and `≫` mean "much less" and "much greater", usually by several orders of magnitude, an informal convention common in engineering and physics. `≠` means only "not equal", without saying which side is larger, and does not require the values to be ordered.

Standard operations preserve inequalities through predictable rules. Adding or subtracting the same number leaves the direction unchanged: `a < b` ⇒ `a + c < b + c`. Multiplying or dividing by a positive number also leaves direction unchanged; multiplying or dividing by a negative number reverses it. The additive inverse reverses direction (`a ≤ b` ⇒ `−a ≥ −b`), and the reciprocal of two same-sign positives reverses direction. Applying a monotonically increasing function (such as the natural logarithm) to both sides preserves direction; a monotonically decreasing function reverses it. If the original inequality is strict and the function is strictly monotonic, the result stays strict; otherwise it becomes non-strict.

Three properties govern how inequalities chain. **Transitivity**: if `a ≤ b` and `b ≤ c`, then `a ≤ c` (and any strict premise yields a strict conclusion). **Converse**: `a ≤ b` and `b ≥ a` are equivalent. **Chained notation**: `a < b < c` is shorthand for "`a < b` and `b < c`", from which `a < c` follows by transitivity. Chains can mix signs (`<`, `=`, `≤`) and mean the logical "and" of each adjacent pair; Python accepts this directly, while C parses `a < b < c` as `(a < b) < c`, a different statement.

Generalising, a **partial order** is a relation `≤` that is reflexive (`a ≤ a`), antisymmetric (`a ≤ b` and `b ≤ a` ⇒ `a = b`), and transitive. Adding the requirement that every pair be comparable gives a **total order**. The real numbers `ℝ` form a total order and, together with `+` and `×`, an **ordered field**: a field whose order is compatible with addition (`a ≤ b` ⇒ `a + c ≤ b + c`) and with multiplication of non-negatives (`0 ≤ a` and `0 ≤ b` ⇒ `0 ≤ ab`). The rationals `ℚ` are also an ordered field, but `ℂ` cannot be: any order on `ℂ` would force both `i² = −1` and `1` to be non-negative, yielding `−1 > 0` and contradicting `−1 + 1 = 0`. A lexicographic order can still be defined on `ℂ` that respects addition but not multiplication.

For positive numbers, four common means chain as `H ≤ G ≤ A ≤ Q`, where `H` is the harmonic, `G` the geometric, `A` the arithmetic, and `Q` the quadratic mean. A widely used named result is **Cauchy–Schwarz**: for vectors `u`, `v` in an inner product space, `|⟨u, v⟩|² ≤ ⟨u, u⟩·⟨v, v⟩`, which in Euclidean `ℝⁿ` becomes `(Σ uᵢvᵢ)² ≤ (Σ uᵢ²)(Σ vᵢ²)`. An inequality is **sharp** if it cannot be loosened without becoming false: `a² ≥ 0` for real `a` is sharp, while `a² ≥ −1` is not.

Systems of linear inequalities define the feasible regions of linear programming and can be solved by Fourier–Motzkin elimination. Systems mixing polynomial equalities and inequalities can be analysed by cylindrical algebraic decomposition, whose cost grows doubly exponentially in the number of variables.
