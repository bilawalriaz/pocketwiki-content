# Pattern language (formal languages)

A pattern language is a formal language defined by a single template string containing both constants and variables, rather than by a grammar or automaton. Every concrete string obtained by replacing each variable with a non-empty string of constants belongs to the language. Dana Angluin introduced pattern languages as a hypothesis space for learning string concepts from examples.

## Building blocks

A pattern is a finite non-empty string over an alphabet Σ of constants together with a countable, disjoint set X of variables. The length |p| counts symbols. P_n is the set of patterns using exactly n distinct variables, and P* is the union over all n.

A substitution f: P* → P* replaces each variable by a non-empty pattern (non-erasing), leaves every constant fixed, and respects concatenation, so f(p⋅q) = f(p)⋅f(q). When a pattern p is obtained from q by some substitution, p is less general than q, written p ≤ q; this forces |p| ≥ |q|.

The language generated by a pattern p is L(p) = { s ∈ Σ⁺ : s ≤ p }, the constant-only strings reachable from p by substitution. Over Σ = {0,1} with variables x, y, …, the pattern xxy generates every bit string formed by repeating a concrete bit string with itself. The pattern 0x10xx1 generates strings like 00z100z0z1 and 01z101z1z1, and L(0x10xx1) ⊆ L(xxy) but 0x10xx1 is not ≤ xxy, because the length-based inclusion equivalence fails when patterns differ in length.

Each pattern p is a common generalisation of all strings in L(p) modulo associativity of concatenation.

## Closure and non-closure

Pattern languages are closed under concatenation, L(p)⋅L(q) = L(p⋅q), and under reversal, L(p)^rev = L(p^rev). They are not closed under union (L(01) ∪ L(10) is not a pattern language), complement (Σ⁺ \ L(0) is not), intersection (L(x0y) ∩ L(x1y) is not), Kleene plus (L(0)⁺ is not), homomorphism, or inverse homomorphism; each non-closure is shown by a small witness no pattern can express.

For single-variable patterns, and for patterns of equal length, p ≤ q holds exactly when L(p) ⊆ L(q). Two patterns generate the same language if and only if they are identical up to a consistent renaming of variables.

## Computational cost

Deciding whether a constant string s belongs to L(p) is NP-complete, as is deciding p ≤ q. The reduction uses 1-in-3-SAT: given a CNF with m clauses and n Boolean variables, one builds a pattern of length 3n+4m+1 with 2n variables and a target string of length 4n+5m+1 whose match corresponds exactly to a 1-in-3 satisfying assignment.

## Position in the Chomsky hierarchy

Pattern languages are incomparable with finite, regular, and context-free languages: L(xx) is not context-free because the pumping lemma fails on it, while {01, 10} is finite but not a pattern language. Every singleton language is a pattern language (use a constant-only pattern), and every pattern language can be produced by an indexed grammar in which the variables of the pattern act as indices threaded through the derivation. In a refined Chomsky hierarchy they sit strictly above the singletons and strictly below the indexed languages, and are incomparable with the families in between, which is why they are usually omitted from the standard table.

## Learning from examples

Given a finite sample S ⊆ Σ⁺, a pattern p is descriptive of S when S ⊆ L(p) and no proper sub-pattern of p covers S. A descriptive pattern can be found by brute force: enumerate all patterns, up to variable renaming, no longer than the shortest string in S; keep those whose language contains S; among those keep the longest; then pick one minimal under ≤. Because the enumeration is exhaustive, the class of pattern languages is identifiable in the limit from positive data, the property Angluin used to motivate the framework.
