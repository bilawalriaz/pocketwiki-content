# High-level programming language

A high-level programming language is a programming language with strong abstraction from the details of the computer. Where assembly and machine code deal directly with registers, memory addresses, and call stacks, a high-level language deals with variables, arrays, objects, arithmetic and Boolean expressions, functions, loops, threads, locks, and other computer-science abstractions. Its elements rarely translate one-to-one to a processor's native opcodes; a compiler or interpreter converts the program into machine-executable instructions, and the programmer hands over much of the control over what those instructions actually are. The amount of abstraction provided defines how "high-level" a language is. Common high-level features also include string handling, object-oriented constructs, and file input/output, so source code can be written and read without reference to any specific machine.

## History

In the early decades of electronic computing, programs were written in machine code or assembly language, which reflected a particular machine's instruction set. High-level languages arose to express algorithms in forms closer to mathematics, business rules, or human-readable procedure, while a compiler or interpreter translated the result into machine-executable instructions. In the 1950s and 1960s the term autocode was often used for such languages.

The earliest high-level language designed for a computer is Plankalkül, developed by Konrad Zuse in the 1940s. It already included structured data, assignment, conditional execution, iteration, and subroutines, but it was not implemented during Zuse's lifetime, and because Zuse worked in wartime and postwar Germany, his work remained largely isolated from later language design.

The first high-level language with wide practical adoption was Fortran, developed at IBM in the 1950s under John Backus. Fortran targeted scientific and numerical computing, letting programmers write algebraic formulas and loops without managing every machine instruction, and demonstrated that compiled high-level languages could produce efficient programs while sharply reducing programming effort. Around the same period, Lisp (John McCarthy) introduced symbolic list processing rooted in the lambda calculus, COBOL became associated with English-like syntax for business data processing, and ALGOL 60 introduced block structure, nested procedures, recursion, lexical scoping, call-by-value versus call-by-name, and Backus–Naur form for defining syntax formally.

From the 1960s onward, languages diversified into distinct programming styles. BASIC made interactive programming accessible in time-sharing and educational settings; Pascal emphasized structured programming and teaching; C combined high-level control structures with low-level access to memory, which made it central to operating systems and system software; Simula introduced the class-and-object model behind object-oriented programming, later extended by Smalltalk around message passing. From the 1980s onward, C++ added classes to C, scripting languages such as Perl, Python, Ruby, and PHP emphasized productivity, and Java promoted portable bytecode on a virtual machine. In the 21st century the focus has shifted to safer abstraction, concurrency, and large codebases: Rust enforces memory and thread safety without a garbage collector, and Go provides simple syntax with built-in concurrency.

## The abstraction penalty

A high-level language standardizes common tasks, permits rich debugging, and maintains architectural agnosticism. A low-level language requires the coder to work at a lower level of abstraction, which is more challenging but allows optimizations not possible in a high-level language. This abstraction penalty is real, but low-level optimizations rarely improve performance at the user-experience level. Even so, code that must run quickly and efficiently may require a lower-level language, and critical portions of a mostly high-level program are often coded in assembly to meet tight timing or memory constraints. A well-designed compiler can produce code comparable to hand-coded assembly, and higher-level abstractions sometimes enable optimizations that beat hand-coded assembly.

## Portability and evolution

Because a high-level language is designed independently of a specific computing architecture, a program written in it can run on any computing context with a compatible compiler or interpreter, and the code can outlive the hardware it was first written for. Low-level programs rarely survive beyond their original system architecture. High-level languages also evolve: new languages aggregate popular constructs with improved features, and some, like Scala, preserve backward compatibility with their predecessors so existing code remains usable after a developer switches.

## Relative meaning

The terms high-level and low-level are inherently relative, and languages are compared as higher or lower level to each other. C is sometimes treated as either high-level or low-level depending on perspective; most agree that C is higher level than assembly and lower level than most other languages. C supports expression evaluation, parameterized and recursive functions, and structured data, but also provides lower-level features such as auto-increment and pointer math, and lacks higher-level abstractions common elsewhere such as garbage collection and a built-in string type. In the introduction of *The C Programming Language*, Kernighan and Ritchie describe C as "not a very high level" language. Assembly is higher-level than machine code but still tied to the processor hardware, and machine code sits at a slightly higher level of abstraction than the microcode or micro-operations used internally in many processors.

## Execution modes

The source code of a high-level language can be processed in several ways. A compiler transforms source code into other code; it may emit native machine code, or generate an intermediate representation such as bytecode that is later interpreted in software or converted to native code at runtime through JIT compilation. Code can also be transpiled into the source of another language, typically a lower-level one, for which a compiler or interpreter is available; JavaScript and C are common targets. A software interpreter performs the actions encoded in source code without producing native machine code. Although uncommon, a processor with a high-level language computer architecture can execute a high-level language without a separate compilation step.

A language is not strictly interpreted or compiled; the label applies to an implementation rather than to the language itself. ALGOL 60 and Fortran have both been interpreted even though they were more typically compiled, and Java is compiled to bytecode that is then executed either by interpretation in a Java virtual machine or by JIT compilation.
