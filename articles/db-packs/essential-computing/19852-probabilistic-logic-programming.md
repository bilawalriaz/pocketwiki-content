# Probabilistic logic programming

Probabilistic logic programming combines ordinary logic programming with probability, so that a program can reason with rules and express uncertainty about facts. It is a programming paradigm rather than a single language, used when a system must draw conclusions from knowledge that is partly logical and partly statistical, such as a medical rule base in which each disease has only a probable link to each symptom.

The dominant approach across the field is the distribution semantics. Under it, a probabilistic logic program is split into two parts: a set of probabilistic facts and a logic program that uses those facts in the bodies of its clauses. A probabilistic fact is a ground atomic formula, a predicate applied to specific constant arguments with no variables, annotated with a probability, as in `0.7 :: stress(anna)`, meaning Anna is stressed with probability 0.7. The probability of any joint choice of truth values for the probabilistic facts is the product of the individual probabilities, which is the assumption that the choices are independent random variables. From this, the program induces a probability distribution over interpretations (truth assignments) of its Herbrand universe, the set of all ground facts built from the program's constants and predicates.

Languages that follow the distribution semantics include Probabilistic Horn Abduction, PRISM, Independent Choice Logic, probabilistic Datalog, Logic Programs with Annotated Disjunctions, ProbLog, P-log, and CP-logic. Many share enough structure that linear-complexity transformations translate one into another, so concepts developed for one language usually carry over.

What makes a probabilistic logic program well behaved depends on the underlying logic. If, for every choice of truth values on the probabilistic facts, the resulting logic program is stratified, meaning no rule's negation depends on a predicate defined later in the program, it has a unique minimal Herbrand model for that choice, and probability flows through without ambiguity. Two important subclasses are positive programs, which omit negation but may be recursive, and acyclic programs, which may use negation but have no recursive dependencies.

When negation creates cycles, the program is unstratified and the stable-model semantics of answer set programming is used. A single truth assignment to the probabilistic facts can then produce several answer sets, and one must decide how to divide probability mass across them. P-Log splits it equally under the principle of indifference. A more cautious alternative is the credal semantics, which assigns a credal set, an interval or, more generally, a closed convex set of probability distributions, to every query: the lower bound counts only truth assignments where the query holds in every answer set (cautious reasoning), and the upper bound counts assignments where it holds in some answer set (brave reasoning).

To answer a ground query, a question with all variables replaced by constants, under the distribution semantics, one sums the probabilities of all worlds (full truth assignments to the probabilistic facts) in which the query is true. This is marginal inference. Listing every world is impractical because their number grows exponentially in the number of ground probabilistic facts. The difficulty is real even in restricted cases: for acyclic programs with atomic queries, computing a conditional probability given evidence is #P-complete, meaning it is at least as hard as counting the satisfying assignments of a propositional formula and is therefore intractable in general.

Because exact inference is hard, two practical routes are used. The first is exact inference via knowledge compilation: the program is converted into a propositional theory and compiled into a target language in which queries are answered in polynomial time. Compilation is the main bottleneck, and researchers compete on producing compact targets that support rich queries and transformations. The second is approximate inference. One variant considers only a subset of the explanations for the query, which yields a lower bound, while a partially expanded set gives an upper bound. Another variant samples ordinary logic programs from the probabilistic program and checks the query in each, estimating its probability as the fraction of samples in which it holds.

Probabilistic inductive logic programming learns these programs from data. Parameter learning estimates the probability annotations of clauses written by the user, often with expectation–maximization or gradient descent; structure learning induces the clauses themselves by searching clause space under a heuristic score. Parameter learning fits the numbers to user-supplied rules, while structure learning discovers the rules themselves, so a system can acquire both the rules and the probabilities of a probabilistic logic program.
